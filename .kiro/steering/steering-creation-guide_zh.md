# 引导文档创建和使用指南

## 什么是引导文档？

引导文档是影响我处理开发任务方式的上下文指南。它们包含项目特定的标准、约定和最佳实践，帮助我提供更相关和一致的协助。

## 引导文档的工作原理

### 包含机制
1. **始终包含（默认）**：没有 front-matter 的文档会包含在每次交互中
2. **文件匹配条件**：带有 `inclusion: fileMatch` 和 `fileMatchPattern` 的文档在特定文件在上下文中时被包含
3. **手动包含**：带有 `inclusion: manual` 的文档只在使用 `#steering-name` 显式引用时被包含

### 上下文集成
- 引导内容在处理用户请求之前被注入到我的系统上下文中
- 我接收适用的引导文档的完整内容
- 多个引导文档可以同时激活
- 使用 `#[[file:path]]` 语法的文件引用会被解析和包含

## 引导文档包含什么

### 我创建的核心类别：

1. **开发环境标准**
   - 本地设置程序
   - 工具配置
   - 环境变量管理
   - 构建和部署流程

2. **代码质量指南**
   - 特定语言的样式指南
   - 命名约定
   - 代码组织模式
   - 文档要求

3. **Git 工作流标准**
   - 分支命名约定
   - 提交信息格式
   - Pull Request 流程
   - 代码审查指南

4. **技术特定标准**
   - 前端开发模式
   - 后端 API 设计
   - 数据库管理
   - 测试策略

5. **安全和性能**
   - 安全最佳实践
   - 性能优化指南
   - 监控和告警标准

### 我遵循的内容结构：

```markdown
---
inclusion: [always|fileMatch|manual]
fileMatchPattern: 'pattern' # if fileMatch
---

# 清晰的标题

## 组织化的章节
- 具体、可操作的指南
- 相关的代码示例
- 工具配置
- 使用 #[[file:path]] 引用外部文件

## 实现细节
- 分步程序
- 要避免的常见陷阱
- 质量检查点
```

## 我如何构建引导文档

### 评估过程：
1. **项目分析**：我检查代码库结构、使用的技术和现有模式
2. **差距识别**：我识别标准会改善一致性的领域
3. **优先级排序**：我首先关注高影响领域（安全、代码质量、工作流程）
4. **模板选择**：我根据项目类型选择适当的模板

### 内容开发：
1. **研究最佳实践**：我从行业标准和经过验证的模式中汲取经验
2. **项目上下文化**：我将通用实践适应特定项目需求
3. **包含示例**：我提供具体的代码示例和配置
4. **引用集成**：我链接到现有项目文件和规范

### 质量保证：
1. **完整性检查**：确保涵盖所有关键领域
2. **一致性验证**：验证指南之间不会冲突
3. **实用性评估**：确认指南是可操作和现实的
4. **更新机制**：计划在项目演进时维护文档

## 包含策略和上下文传输

### 发送的内容：
- **完整内容**：完整的引导文档内容被传输
- **已解析的引用**：使用 `#[[file:path]]` 引用的文件被读取并包含
- **多个文档**：所有适用的引导文档被合并
- **实时评估**：每次交互都会评估包含规则

### 文档何时被包含：
- **始终**：没有 front-matter 文档的默认行为
- **文件上下文触发**：当对话上下文中有特定文件模式时
- **手动触发**：当用户使用 `#steering-name` 显式引用时
- **自动解析**：系统根据文件模式确定相关性

### 上下文限制：
- 如果大型引导文档超过上下文限制，可能会被截断
- 优先考虑更具体/相关的引导文档
- 最近的交互可能影响哪些文档被优先考虑

## 引导创建的最佳实践

### 应该做：
- 保持文档专注和具体
- 使用清晰、可操作的语言
- 包含具体示例
- 引用外部规范
- 随着项目演进定期更新
- 使用适当的包含机制

### 不应该做：
- 创建过于宽泛或通用的指南
- 在多个文档中重复信息
- 包含敏感信息或机密
- 创建冲突的标准
- 使文档过长或复杂

## 维护和演进

### 定期审查：
- 评估现有引导文档的有效性
- 根据项目变化和学习进行更新
- 删除过时或冲突的指南
- 随着项目增长添加新标准

### 反馈集成：
- 监控引导文档如何影响代码质量
- 根据团队反馈和开发模式进行调整
- 改进包含模式以提高相关性
- 优化文档结构以提高清晰度

## 技术实现说明

### 文件结构：
```
.kiro/steering/
├── project-standards.md (always included)
├── git-workflow.md (always included)
├── frontend-standards.md (fileMatch: *.tsx,*.jsx)
├── api-design.md (manual inclusion)
└── development-environment.md (fileMatch: package.json)
```

### Front-matter 选项：
```yaml
---
inclusion: always|fileMatch|manual
fileMatchPattern: 'glob-pattern' # for fileMatch only
---
```

### 文件引用语法：
```markdown
#[[file:relative/path/to/file.ext]]
```

这创建了一个综合系统，用于维护项目一致性并在整个开发过程中提供上下文指导。
